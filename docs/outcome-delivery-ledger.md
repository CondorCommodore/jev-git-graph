## Verification policy

Prioritize complete implementation. Do not target a coverage percentage or add
large suites of implementation-mirroring mocks. Use installed-package outcomes
and a small number of adverse checks at source-disclosure and destructive-action
boundaries. Existing required checks remain landing gates. A synthetic result
is labeled simulation and cannot satisfy the real model utility or real cleanup
requirements. Review receipts, test results, provider dispatch, merged code and
actual deleted refs each require their own direct evidence.

## Approval boundaries

The build is authorized. New Jev evidence requires an exact prepared request
manifest and approval. Real cleanup requires its concrete verified recovery
bundle and exact manifest approval. Neither boundary blocks independent build
work. A model answer cannot authorize deletion. Non-EXACT archive-backed deletion,
worktree removal and stash dropping require their own specified preservation
policy and explicit approval if they become necessary.
